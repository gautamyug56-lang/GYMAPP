# Stage 7 — Churn Prediction

## Method

Rackroom predicts whether an active member is likely to churn using a binary classification model in ML.NET.

The model uses these features:

- visits per week
- recent visits
- attendance decline
- days since last visit
- membership length
- membership type/duration
- payment history
- approved pause count

The production scoring service excludes members who are currently inside an approved membership pause.

## Synthetic dataset

Rackroom has no real gym dataset, so the training data is explicitly synthetic.

The generator creates 3,000 deterministic records using a fixed seed. The label is sampled from a logistic risk function designed around the business assumption that lower attendance, larger attendance decline, longer inactivity and weaker payment history increase churn probability.

This is a simulation for demonstrating the ML pipeline, not evidence of real-world churn rates.

The generator checks that both classes have at least 30% of the dataset to avoid a severely imbalanced synthetic sample.

## Model comparison

Three ML.NET trainers are compared:

1. SDCA Logistic Regression
2. FastTree
3. LightGBM

The test set is 20% of the synthetic data.

The selected model is the one with the highest F1 score, with AUC used as the tie-breaker.

The evaluation records:

- precision
- recall
- F1
- ROC AUC
- true positives
- false positives
- true negatives
- false negatives

Accuracy is deliberately not used as the sole selection metric.

## Feature drivers

Permutation Feature Importance (PFI) is calculated on the selected model. ML.NET describes PFI as a model-agnostic method that measures how model performance changes when feature values are permuted.

The resulting feature importance values are stored with each churn prediction so the dashboard can show the global model drivers.

## Scoring

The trained model is saved as:

`App_Data/ml/churn-model.zip`

The training report is saved as:

`App_Data/ml/churn-training-report.json`

A nightly BackgroundService scores active members. Members currently paused are excluded.

Risk levels:

- Low: probability < 0.33
- Medium: 0.33–0.6599
- High: >= 0.66

## Report write-up

**Method:** Rackroom uses a synthetic, business-assumption-driven dataset because real gym data was unavailable. Eight behavioural and membership features are used to train three ML.NET binary classifiers. The models are evaluated on a held-out test set using precision, recall, F1 and ROC AUC, with a confusion matrix used to inspect classification errors. The model with the best F1 score, using AUC as a tie-breaker, is saved for production scoring. Permutation Feature Importance is then used to identify the strongest global feature drivers.

**Results:** The exact numerical results are generated by the training page and saved in `App_Data/ml/churn-training-report.json`. They should be copied into the final report after running the training job; no performance numbers are fabricated in this repository. The final report should include the three trainer metrics, selected model, confusion matrix and top PFI features.

## Limitations

Because the dataset is synthetic, the resulting performance metrics measure the model's ability to recover the synthetic assumptions. They do not establish real predictive accuracy for Nepalese gym members. A future deployment should retrain and recalibrate the model using anonymized real gym data.
